Fire vs Fire isn’t limited to AI detection—that’s why ResNet 50 - Spider exists! Any Python class inheriting from BaseClassifier placed in native/classifiers/ is automatically discovered and loaded by the Native Host. Here is the complete interface: 

from abc import ABC, abstractmethod
from typing import List, Dict, Any, Optional, Set
from pathlib import Path
import sys

class BaseClassifier(ABC):
    """Abstract base class for AI detection classifiers (multi-modal)."""

    def __init__(self, model_path: Optional[Path] = None):
        self.model_path = model_path
        self.model = None
        self.device = None
        self._is_loaded = False

    @abstractmethod
    def get_supported_modalities(self) -> Set[str]:
        """Return supported modalities: {'image'}, {'text'}, {'audio'}, or {'video'}."""
        pass

    @abstractmethod
    def load_model(self) -> tuple[bool, Optional[str]]:
        """Load weights onto device. Return (success: bool, error_reason: Optional[str])."""
        pass

    @abstractmethod
    def preprocess_batch(self, inputs: List[Any], modality: str) -> tuple[Any, List[int]]:
        """Preprocess inputs for inference. Return (batch_tensor, valid_indices)."""
        pass

    @abstractmethod
    def classify_batch(self, batch_tensor: Any) -> List[float]:
        """Run model inference. Return List of scores in [0.0, 1.0], or -1.0 for error."""
        pass

    @abstractmethod
    def get_device_info(self) -> Dict[str, Any]:
        """Return dict with keys: 'device', 'name', 'backend' (e.g. CUDA, DirectML, CPU)."""
        pass

    @abstractmethod
    def get_model_name(self) -> str:
        """Return human-readable model name."""
        pass

    def get_label(self) -> str:
        """Human-readable badge label (e.g. 'AI generated', 'Spider')."""
        return "AI generated"

    def is_loaded(self) -> bool:
        """Check if model is currently loaded in memory."""
        return self._is_loaded

    def unload_model(self):
        """Unload model from memory for resource efficiency."""
        self.model = None
        self._is_loaded = False

    def process_batch(self, inputs: List[Any], modality: str) -> List[float]:
        """Convenience method combining load_model, preprocess_batch, and classify_batch."""
        if not self.is_loaded():
            success, _ = self.load_model()
            if not success:
                return [-1.0] * len(inputs)
        batch_tensor, valid_indices = self.preprocess_batch(inputs, modality)
        if not valid_indices:
            return [-1.0] * len(inputs)
        scores = self.classify_batch(batch_tensor)
        results = [-1.0] * len(inputs)
        for idx, score in zip(valid_indices, scores):
            results[idx] = score
        return results

    def _log_to_stderr(self, message: str) -> None:
        """Safe stderr logging to avoid corrupting native messaging JSON on stdout."""
        try:
            print(message, file=sys.stderr, flush=True)
        except Exception:
            pass

01

The Dual Architecture: Why an Extension + Native Host?

Solving the browser sandboxing and compute limits

People often ask: "Why do I need to download a local Python server? Why can't a browser extension just classify everything directly in JavaScript?"

The answer comes down to silicon and sandboxing. Modern state-of-the-art vision models (such as Heimdall 04, 24-channel FFT forensic nets, and ConvNeXt-Base backbones) require hundreds of megabytes of neural parameters and billions of floating-point operations.

Browser extensions operate inside isolated JavaScript Web Workers. These environments are strictly memory-capped (typically 2 to 4 GB shared across all browser tabs) and are strictly barred by browser security from accessing low-level hardware handles—like NVIDIA Tensor Cores, CUDA device streams, or AMD DirectML pipelines. Running models inside the browser would instantly freeze tabs, exhaust RAM, and stutter user scrolling.

⚡ The Two-Halves Solution:
  • The Browser Extension (The Eyes): Scans the DOM as pages render, intercepts visible images and paragraphs, applies visual styling (hover blurs, border glows, info badges), and manages user preferences.
  • The Native Inference Host (The Brain): A lightweight, standalone Python engine running natively on your operating system. It interfaces directly with your GPU (CUDA, DirectML, MPS) or CPU, holding models warm in memory for instantaneous matrix math.
  • Native Messaging Bridge: The browser and the host communicate locally via standard OS pipes (stdin / stdout) in structured JSON packets—fast, private, and requiring zero network overhead.
02

The Zero-Internet Privacy Guarantee

100% on-device processing: what you browse never leaves your PC

In an era where most AI tools send user data, prompts, and photos to cloud data centers for processing, Fire vs Fire takes an uncompromising stance on privacy:

  • No Cloud Roundtrips: Every single classification happens strictly inside your computer's RAM and GPU.
  • Zero Inbound Ports & Zero Outbound Sockets: The Native Host has zero network listening sockets. During classification, it does not send telemetry, ping analytics servers, or transmit your visited URLs.
  • Air-Gapped Safety: If you unplug your Ethernet cable or disconnect from Wi-Fi, Fire vs Fire continues to classify web images and text without missing a beat.
  • Encrypted Pipeline: Even when transferring images from the browser to the local Python host, data flows purely through your operating system's local memory IPC pipes.
03

Dynamic Prioritization & Single-Item Streaming

How Fire vs Fire eliminates lag and stale queue bottlenecks

Early prototypes collected images into static batches (e.g., 16 items) and waited for the batch to fill before dispatching. However, in real-world browsing—especially when rapidly switching between tabs or scrolling social feeds—static batches create massive latency. When you switch tabs, the old queue continues churning through images you aren't even looking at!

Our Dynamic Prioritization Engine (v2.2) introduces a smart 3-tier priority schedule:

Priority 0 • Immediate Active Viewport

Content directly visible on your physical screen right now. These items jump to the front of the queue and are classified instantly.

Priority 1 • Background Offscreen Fold

Content located below the fold is queued asynchronously. As you scroll downward, it is already tagged before you reach it.

Priority 2 • Auto-Purge Inactive Tabs

If you switch to another browser tab or navigate away, pending tasks from the previous page are instantly dropped so hardware is never wasted.

Additionally, individual large media payloads are dynamically sliced into safe chunks beneath the 1 MB Native Messaging packet limit and reconstructed seamlessly on the other side.

04

Sub-Millisecond In-RAM Content Caching

Eliminating redundant neural forward passes

Modern websites reuse the same assets repeatedly: author avatars on forum threads, website brand logos, navigation buttons, and viral memes shared across multiple posts.

Fire vs Fire incorporates an in-memory LRU Content Cache inside the Native Host:

  • Upon arrival, each media payload is hashed with a high-throughput perceptual checksum.
  • If the hash matches an item classified earlier in your session, the Native Host bypasses the neural forward pass entirely and returns the cached probability in under 0.5 milliseconds.
  • This reduces GPU thermals, prevents unnecessary battery consumption, and ensures instantaneous tagging on frequently visited domains.
05

Battery Awareness & Thermal Efficiency

Intelligent power policies for laptop users

High-end deep learning inference can draw noticeable power on mobile devices. Fire vs Fire provides native power awareness directly integrated into the master switch:

  • AC Power Detection: The Native Host queries Windows Kernel / OS power APIs to detect whether your laptop is plugged into the wall or running on battery.
  • "Only when plugged in": Toggle this sub-button to automatically pause classification whenever you unplug, preserving battery for browsing.
  • "Pause below threshold": Set a safety threshold (e.g. 20%). If your battery dips below this level, Fire vs Fire gently stands down until recharged.
  • "Keep the Engine Warm": Unlike command-line scripts that reboot Python and reload 200 MB model weights for every image, Fire vs Fire keeps the neural engine warm in memory while browsing, preventing disk thrashing and high CPU initialization spikes.

Frequently Asked Questions & Troubleshooting

Quick answers to common questions
Q: What do the toolbar flame icons and counters mean?

A green flame with a counter means active scanning is in progress (the counter indicates remaining items). A red flame means the local AI host is connected, healthy, idle, and standing by. A muted flame means the Native Host is disconnected.

Q: How do I test if my Native Host is working?

Click the flame icon in your browser bar, select Options, open the Advanced panel, and click ⚡ Test Connection. It will ping the native host and report your GPU/CPU device info.

Q: Can I build my own custom classifiers?

Yes! Fire vs Fire is fully extensible. Any Python script inheriting from BaseClassifier placed in native/classifiers/ is automatically discovered and loaded into the Options category selector.
